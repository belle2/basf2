Changes in the analysis package in light-2609-luna
--------------------------------------------------

ModeSelector
++++++++++++
* Added `ModeSelector`, an event-level classifier on top of the hadronic FEI. It uses all FEI :math:`B` candidates of an event together to predict the :math:`B` type and the decay mode of the tag :math:`B`, which mainly reduces :math:`B^0` / :math:`B^+` crossfeed.
* Its models are taken from a performance globaltag instead of the analysis globaltag. The payload names carry no campaign or training version, so the training is selected by the globaltag alone. See :ref:`mva_contract_version` for the contract version scheme.

FlavorTagger
++++++++++++
* TFlaT: fixed a bug affecting events with multiple signal side B candidates: The ranking of tracks in the ROE was only done for the first B candidate and not refreshed for later candidates. After the bugfix, the effective tagging efficiency improved slightly. Using the bugfixed version is the new recommendation.
* Category-based: the ``FANN``-based combination method (``FANN_qrCombined``) is no longer available, as basf2 no longer supports ``FANN``. The only available combination method is the ``FastBDT``-based one (``FBDT_qrCombined``). This change does not affect GFlaT or TFlaT.

sysvar (former pidvar)
++++++++++++++++++++++
* Added a ``seed`` argument to ``Reweighter.add_pid_particle``, ``Reweighter.add_fei_particle`` and ``add_weights_to_dataframe``. It makes both the systematic and the statistical weight variations reproducible, so a weight table gives the same variations in every dataframe it is applied to, while the variations of different tables remain independent. The previous ``sys_seed`` argument only seeded the systematic variations and initialised a random seed for the statistical variations, so they were not reproducible. It is kept for backward compatibility but now issues a warning.
* Fixed the coverage plots of ``ReweighterParticle.plot_coverage`` for a single particle hypothesis or binning variable, and a pandas warning when adding FEI weight columns.

Variables
+++++++++
* Deprecated the single-argument form of `weMissE`, `weMissM2`, `weMissP`, `weMissPTheta`, `weMissPx`, `weMissPy` and `weMissPz`, which relied on the default ROE mask name ``all``. It now issues a warning; the ROE mask name will become a mandatory argument in a future release.
* Improved documentation for the Helicity, FEI, Basic Particle Information variable groups
* Removed the Calibration variable group from the analysis package
* Improved documentation for the Helicity and FEI variable groups.
* Added :b2:var:`nParticlesInCone` to count Track, ECLCluster and KLMCluster particles within a cone.
* Deprecated the single-argument form of `weMissE`, `weMissM2`, `weMissP`, `weMissPTheta`, `weMissPx`, `weMissPy` and `weMissPz`, which relied on the default ROE mask name ``all``. It now issues a warning; the ROE mask name will become a mandatory argument in a future release.
* Improved documentation for the Helicity and FEI variable groups

Modules and Modular Analysis
++++++++++++++++++++++++++++
* Deprecated the ``Pi0VetoEfficiencySystematics`` module and `modularAnalysis.addPi0VetoEfficiencySystematics`, which will be removed in February 2027. The pi0 veto Data/MC efficiency weights can be obtained with the generic `ParticleWeighting` module. See the documentation of `modularAnalysis.addPi0VetoEfficiencySystematics` for details.
* `ParticleWeighting` no longer throws an exception when ``selectedDaughters`` is used and the same daughter is shared by several candidates of the input list.

Changes in the analysis package in light-2607-kasei
---------------------------------------------------

Modules and Modular Analysis
++++++++++++++++++++++++++++
* `modularAnalysis.scaleTrackMomenta` and `modularAnalysis.correctTrackEnergy` now let basf2 automatically choose the data or MC version of the correction payload: the suffix ``_data`` or ``_MC`` is appended to the given ``payloadName`` depending on whether the module runs on data or MC.
* Updated the documentation of `modularAnalysis.correctBrems`, `modularAnalysis.correctBremsBelle` and the `BremsFinder` module to follow the current Bremsstrahlung recovery recommendation: since release-08 (proc16, MC16) `modularAnalysis.correctBrems` is preferred.
* `modularAnalysis.printMCParticles` has a new ``storeCompact`` argument to store a compact single-line representation of the decay tree in the ``__MCDecayString__`` branch instead of the full indented tree.

Variables
+++++++++
* Added metavariable `varForNthDaughterOfType`, which searches a given number of daughter generations of the given particle for the nth particle of the given type and, if such a particle exists, returns the given variable for it, otherwise NaN.

Command line tools
++++++++++++++++++
* Removed deprecated ``-mc`` / ``--mccampaign`` argument and added release 9 as an option to ``-r`` / ``--release`` argument in :ref:`b2help-recommendation`

FEI
+++
* Added optional argument ``extraPathSpec`` to allow specifying inside the channels list to add additional basf2 modules to the FEI path.

Changes in the analysis package in light-2604-jellyfish
-------------------------------------------------------

Standard Particle Lists
+++++++++++++++++++++++
* Deprecated most standard particle lists in `stdCharged`, `stdPhotons`, `stdPi0s`, and `stdHyperons`, with removal planned at the end of 2026. 

Modules and Modular Analysis
++++++++++++++++++++++++++++
* It is no longer possible to use ``tree`` as the name for a ``TTree`` saved with the `VariablesToNtuple` and `VariablesToEventBasedTree` modules. In particular, this affects the argument ``treeName`` of the function `modularAnalysis.variablesToNtuple`: ``variablesToNtuple(treeName='tree')`` will now result in a ``FATAL`` message from basf2.

Variables
+++++++++
* Added metavariable `atan2`, which returns the atan2 value (arctangent of y/x). The result is in radians. 
* Added variables `nCDCDedxLayers`, which returns number of CDC layers with dE/dx measurements used in PID likelihood and `trackQualityIndicator`, which returns fake/real track classification (0 = likely fake).

FlavorTagger
++++++++++++
* Updated TFlaT and added config for Belle.

Changes in the analysis package in light-2603-ina
-------------------------------------------------

Variables
+++++++++
* As a substitute for `klmClusterTrackDistance` which is only available for release-10 mDSTs, a new variable `klmClusterTrackDistance_helix_extrapolation` is provided for analysts to be used with release-09 or ealier mDSTs.
* Added FEI-related variable :b2:var:`sigProbRank(bp_list, b0_list) <sigProbRank>` to rank candidates across both B+ and B0 lists by descending ``extraInfo(SignalProbability)``.
* Added FEI-related variables `mostcommonBTagDeltaP` and `mostcommonBTagPDG` for accessing the generated B meson momentum difference and PDG code identified by `mostcommonBTagIndex`.
